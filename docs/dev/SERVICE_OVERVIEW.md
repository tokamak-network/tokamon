# Tokamon - 서비스 기획서

## 서비스 개요

### 한 줄 소개
점주가 매장에 TON을 걸고, 방문한 고객에게 보상하는 위치 기반 리워드 플랫폼

### 서비스 컨셉
- 점주: TON을 예치하여 매장 방문 유도 + 스탬프로 단골 확보
- 사용자: 매장 방문만으로 TON 획득 + 스탬프 보너스
- 플랫폼: 점주와 사용자를 연결하는 중개 역할

---

## 핵심 가치 제안

### 점주 관점
- 실제 매장 방문을 유도할 수 있음 (온라인 광고와 달리 측정 가능)
- 스탬프 시스템으로 단골 고객 확보
- 예치한 TON이 방문자에게만 지급되므로 예산 낭비 없음
- TON 소진 시 자동 종료되어 비용 통제 가능

### 사용자 관점
- 매장 방문만으로 TON을 받을 수 있음
- 스탬프를 모으면 보너스 보상
- 새로운 매장 발견의 재미
- 받은 TON은 실제 환전 가능

---

## 서비스 참여자

### 1. 점주 (매장 운영자)
**역할**: 스팟 등록 + TON 예치 + 방문 보상 제공 + 단골 관리

**사용 흐름**:
1. Tokamon에 매장 등록
2. 스팟 설정:
   - 매장 위치, 이름, 설명
   - 1회 방문 보상 (예: 0.1 TON)
   - 스탬프 목표 횟수 (예: 10회)
   - 스탬프 달성 보너스 (예: 2 TON)
   - 재방문 쿨다운 (예: 24시간)
3. TON 예치 → 스팟 즉시 활성화 (예치 = 광고 시작)
4. 방문자 현황 확인
5. TON 소진 → 자동 비활성화 (광고 종료)
6. 계속하려면 새로 예치

### 2. 사용자 (방문자)
**역할**: 매장 방문 + TON 수령 + 스탬프 수집

**사용 흐름**:
1. 앱에서 주변 스팟 확인
2. 매장으로 이동
3. 50m 이내 접근 시 클레임 → TON 수령
4. 같은 매장 재방문 시 쿨다운 이후 다시 클레임 가능
5. 스탬프 목표 달성 시 보너스 TON 획득
6. 스탬프 리셋 → 다시 1회부터

---

## 스탬프 시스템

### 구조

점주가 스팟 생성 시 다음을 설정:

| 설정 항목 | 설명 | 예시 |
|----------|------|------|
| 1회 방문 보상 | 방문할 때마다 받는 TON | 0.1 TON |
| 스탬프 목표 | 보너스를 받기 위한 방문 횟수 | 10회 |
| 스탬프 보너스 | 목표 달성 시 추가 보상 | 2 TON |
| 쿨다운 | 같은 사용자의 재방문 클레임 간격 | 24시간 |

### 사용자 경험

```
1회 방문 → 0.1 TON + 스탬프 1/10
2회 방문 → 0.1 TON + 스탬프 2/10
  ...
10회 방문 → 0.1 TON + 보너스 2 TON! (스탬프 10/10 달성)
스탬프 리셋 → 다시 1/10부터
```

### 점주 관점 예산 계산

```
설정:
- 1회 보상: 0.1 TON
- 스탬프 목표: 10회
- 스탬프 보너스: 2 TON
- 총 예치: 30 TON

비용 구조 (1명의 사용자가 10회 방문 시):
- 일반 보상: 0.1 × 10 = 1 TON
- 스탬프 보너스: 2 TON
- 1명당 총 비용: 3 TON

30 TON으로 10명의 단골 고객 확보 가능
```

## 핵심 규칙

### 예치와 광고
- TON 예치 = 광고 시작 (즉시 활성화)
- TON 소진 = 광고 종료 (자동 비활성화)
- 환불 없음 (예치 = 광고비 집행)
- 계속하려면 새로 예치

### 클레임 조건
- 스팟 중심 50m 이내 접근
- 쿨다운 시간 경과 (점주 설정)
- 스팟에 TON 잔액 있음
- GPS 정확도 검증 통과

### 수수료
- 초기: 수수료 0% (점주 예치금 100%가 사용자 보상)
- 추후: 사용자 기반 확보 후 수수료 모델 도입

## 상세 사용 시나리오

### 시나리오 1: 직장인 김철수씨 (28세)

**상황**: 점심시간에 주변 매장 둘러보기

```
12:00 - 앱 실행, 지도 확인
       → "이영희 카페" 발견 (300m) - 0.1 TON
       → "홍길동 피자" 발견 (500m) - 0.15 TON

12:10 - 이영희 카페 도착, 클레임
       → 0.1 TON 획득
       → 스탬프 4/10 (6번 더 오면 보너스 2 TON!)
       → 커피 구매

12:30 - 홍길동 피자 도착, 클레임
       → 0.15 TON 획득
       → 스탬프 1/5 (첫 방문)
       → 점심 식사

13:00 - 오늘 획득: 0.25 TON
       → 이영희 카페 단골까지 6회 남음
```

### 시나리오 2: 카페 사장님 이영희씨 (35세)

**상황**: 신규 고객 유치 + 단골 확보

```
[기존 광고 방식]
- 네이버 광고: 월 30만원, 클릭만 발생, 실제 방문 불확실
- 전단지: 월 20만원, 효과 측정 불가

[Tokamon 사용]
스팟 설정:
- 1회 보상: 0.1 TON
- 스탬프: 10회 방문 시 2 TON 보너스
- 쿨다운: 24시간
- 예치: 30 TON

결과 (1개월 후):
- 방문자: 150명
- 이 중 10회 달성(단골): 10명
- 소비한 TON: 30 TON
- 단골 고객 10명 확보
```

## 기술 아키텍처

### 시스템 구성도

```
[React 웹 클라이언트]
  - Leaflet 지도
  - GPS 위치 추적
  - 스팟 생성/클레임
        │
        │ REST API
        ↓
[Express 백엔드]
  - 위치 검증 (50m, haversine)
  - 쿨다운 검증
  - 스탬프 관리
  - 속도 검증 (GPS 스푸핑 방지)
        │
        │ ethers.js
        ↓
[스마트 컨트랙트 (Solidity)]
  - 잔액 관리
  - 스팟 예치금 관리
  - 클레임 기록
  - 스탬프 카운트
```

### 기술 스택

| 영역 | 기술 |
|------|------|
| 프론트엔드 | React 18 + Vite + Leaflet |
| 백엔드 | Node.js + Express |
| 블록체인 | Solidity 0.8.19 (EVM) |
| 개발환경 | Ganache (로컬 EVM, 포트 8999) |

### 스마트 컨트랙트 핵심 함수

| 함수 | 설명 |
|------|------|
| `deposit()` | 점주가 TON 예치 |
| `createSpot()` | 스팟 생성 (보상, 스탬프 목표, 보너스, 쿨다운 설정) |
| `claim()` | 사용자 클레임 (쿨다운 확인, 스탬프 증가, 보너스 지급) |
| `getBalance()` | 잔액 조회 |
| `getStampCount()` | 사용자의 스팟별 스탬프 현황 조회 |

| 항목 | 방법 |
|------|------|
| 위치 검증 | GPS 거리 계산 (haversine, 50m 이내) |
| 재방문 제한 | 쿨다운 시간 검증 (점주 설정) |
| GPS 스푸핑 방지 | 이동 속도 검증 (max 300km/h) |
| 중복 방지 | 컨트랙트에서 마지막 클레임 시간 기록 |

## 스팟 라이프사이클

```
[점주 TON 예치]
      ↓
[스팟 활성화] ←── 재예치
      ↓
[사용자 방문 + 클레임]
      ↓
[TON 소진]
      ↓
[스팟 비활성화]
```

- 활성: TON 잔액 있음, 클레임 가능
- 비활성: TON 소진, 지도에서 회색 표시
- 재활성화: 점주가 추가 예치하면 다시 활성

## 시장 분석

### 타겟 시장

**점주 (돈을 내는 고객)**:
- 소상공인 (카페, 음식점, 소매점): 신규 고객 유치 + 단골 확보 필요
- 프랜차이즈: 지역 매장별 프로모션
- 팝업스토어/행사: 단기 방문 유도

**사용자 (서비스를 쓰는 고객)**:
- 주변 매장에서 혜택 받고 싶은 일반인
- 점심시간/퇴근길 활용하려는 직장인
- 새로운 매장을 발견하고 싶은 사람

### 경쟁 분석

| 서비스 | 형태 | Tokamon과의 차이 |
|--------|------|-----------------|
| 네이버 플레이스 광고 | 검색 광고 (클릭 과금) | Tokamon은 실제 방문에만 과금 |
| 당근마켓 광고 | 지역 광고 (노출 과금) | Tokamon은 방문 + 단골 확보 |
| 매장 자체 스탬프 카드 | 종이/앱 스탬프 | Tokamon은 TON 보상이 추가됨 |
| 캐시워크 | 걷기 보상 (배너 광고 수익) | Tokamon은 점주가 직접 보상 |

### 차별점
- 점주가 직접 방문자에게 보상 → 중간 단계 없음
- 실제 방문에만 비용 발생 → 광고비 낭비 없음
- 스탬프로 재방문 유도 → 일회성 광고가 아닌 단골 확보
- TON 기반 → 투명한 정산, 즉시 지급

## 수익 모델

### 초기 (사용자 확보 단계)
- 수수료 0%
- 점주 예치금이 100% 사용자에게 지급
- 목표: 점주와 사용자 확보에 집중

### 성장기 (수수료 도입)
- 예치 시 수수료 부과 (예: 5~10%)
- 또는 프리미엄 점주 기능 유료화 (상세 통계, 우선 노출 등)

### 장기
- 점주 대시보드 유료 기능
- 프랜차이즈 패키지 (다수 매장 일괄 관리)
- 데이터 분석 리포트 (방문 패턴, 유동인구)

## 성장 전략

### Phase 1: MVP (1~3개월)
- 핵심 기능 완성 (스팟 생성, 클레임, 스탬프)
- 파일럿 점주 확보 (수수료 0%로 진입 장벽 제거)
- 소규모 지역에서 테스트 (예: 강남역 주변)

### Phase 2: 초기 성장 (4~6개월)
- 점주 50개, 사용자 1,000명 목표
- 성공 사례 기반 점주 확대
- 사용자 리텐션 데이터 수집 및 개선

### Phase 3: 확장 (7~12개월)
- 수수료 모델 도입
- 프랜차이즈 제휴
- 서울 전역 → 수도권 확장

### Phase 4: 스케일업 (12개월+)
- 전국 확장
- 점주 대시보드 고도화
- 해외 진출 검토

## 핵심 성공 요인

1. **초기 점주 확보**: 수수료 0%로 진입 장벽 제거, 파일럿 프로그램
2. **스팟 밀도**: 사용자 주변에 스팟이 충분해야 앱을 계속 사용
3. **단골 전환**: 스탬프 시스템이 실제로 재방문을 유도하는지 검증
4. **위치 보안**: GPS 스푸핑 방지가 신뢰도의 핵심
5. **간편한 UX**: 점주도 사용자도 쉽게 쓸 수 있어야 함
