# Tokamon - 사용자 유즈케이스

## 참여자

| 참여자 | 설명 |
|--------|------|
| 점주 | 매장을 운영하며 TON을 예치하여 방문 보상을 제공하는 사람 |
| 사용자 | 매장을 방문하여 TON을 수령하는 사람 |
| 시스템 | Tokamon 플랫폼 (서버 + 스마트 컨트랙트) |

---

## 점주 유즈케이스

### UC-1: 지갑 연결

**목적**: 점주가 Tokamon에 지갑을 연결한다

**흐름**:
1. 점주가 Tokamon 앱에 접속한다
2. "지갑 연결" 버튼을 누른다
3. MetaMask 지갑 승인 팝업이 뜬다
4. 점주가 승인한다
5. 지갑 주소가 연결되고 잔액이 표시된다

**예외**:
- MetaMask 미설치 → 설치 안내 메시지

---

### UC-2: TON 충전

**목적**: 점주가 스팟 생성을 위해 TON을 충전한다

**사전 조건**: UC-1 완료 (지갑 연결됨)

**흐름**:
1. 점주가 "충전" 버튼을 누른다
2. 충전할 TON 금액을 입력한다
3. MetaMask 트랜잭션 승인 팝업이 뜬다
4. 점주가 승인한다
5. 내부 잔액에 TON이 추가된다
6. 갱신된 잔액이 화면에 표시된다

**예외**:
- 지갑 잔액 부족 → "지갑 잔액이 부족합니다" 메시지
- 트랜잭션 실패 → "충전에 실패했습니다. 다시 시도해주세요" 메시지

---

### UC-3: 스팟 생성

**목적**: 점주가 매장 위치에 리워드 스팟을 등록한다

**사전 조건**: UC-2 완료 (충분한 TON 잔액)

**흐름**:
1. 점주가 "스팟 만들기" 탭을 선택한다
2. 지도에서 매장 위치를 탭하여 핀을 찍는다
3. 스팟 정보를 입력한다:
   - 매장 이름 (필수)
   - 설명 (필수)
   - 1회 방문 보상 (예: 0.1 TON)
   - 스탬프 목표 횟수 (예: 10회)
   - 스탬프 달성 보너스 (예: 2 TON)
   - 재방문 쿨다운 (예: 24시간)
   - 활성 시간대 (예: 09:00 ~ 22:00)
   - 총 예치 금액 (예: 30 TON)
4. 예상 정보가 자동 계산되어 표시된다:
   - 1명이 스탬프 달성 시 비용: (보상 × 목표) + 보너스
   - 예치금으로 가능한 단골 고객 수
5. 점주가 "스팟 생성" 버튼을 누른다
6. 잔액에서 예치금이 차감된다
7. 스팟이 지도에 활성 상태로 표시된다

**예외**:
- 잔액 부족 → "잔액이 부족합니다. 충전 후 다시 시도해주세요"
- 보상이 0 이하 → "보상 금액을 입력해주세요"
- 예치금 < 보상 → "예치금은 1회 보상 이상이어야 합니다"

---

### UC-4: 스팟 재예치

**목적**: TON이 소진된 스팟에 추가 예치하여 다시 활성화한다

**사전 조건**: UC-3으로 생성한 스팟이 존재함

**흐름**:
1. 점주가 자신의 스팟을 선택한다
2. 현재 상태를 확인한다 (남은 TON, 총 방문자 수)
3. "재예치" 버튼을 누른다
4. 추가 예치할 TON 금액을 입력한다
5. 잔액에서 차감되고 스팟의 남은 TON이 증가한다
6. 스팟이 다시 활성 상태가 된다

**예외**:
- 본인 스팟이 아닌 경우 → "재예치" 버튼이 표시되지 않음
- 잔액 부족 → "잔액이 부족합니다"

---

### UC-5: 방문 현황 확인

**목적**: 점주가 자신의 스팟 방문 현황을 확인한다

**사전 조건**: UC-3으로 생성한 스팟이 존재함

**흐름**:
1. 점주가 자신의 스팟을 선택한다
2. 다음 정보를 확인한다:
   - 남은 TON / 총 예치 TON
   - 총 클레임 횟수
   - 스탬프 달성(단골) 고객 수
   - 최근 클레임 내역

---

## 사용자 유즈케이스

### UC-6: 지갑 연결

**목적**: 사용자가 Tokamon에 지갑을 연결한다

**흐름**: UC-1과 동일

---

### UC-7: 주변 스팟 탐색

**목적**: 사용자가 주변의 리워드 스팟을 확인한다

**사전 조건**: UC-6 완료 (지갑 연결됨)

**흐름**:
1. 앱이 사용자의 현재 위치를 GPS로 확인한다
2. 지도에 주변 스팟이 마커로 표시된다:
   - 초록색: 활성 스팟 (클레임 가능)
   - 노란색: 쿨다운 중 (재방문 대기)
   - 회색: TON 소진 (비활성)
3. 마커를 탭하면 스팟 정보가 표시된다:
   - 매장 이름, 설명
   - 1회 보상
   - 스탬프 현황 (내 스탬프 / 목표)
   - 현재 위치에서 거리
   - 쿨다운 남은 시간 (있을 경우)

**예외**:
- GPS 권한 거부 → "위치 권한이 필요합니다" 안내
- 주변에 스팟 없음 → "근처에 스팟이 없습니다" 메시지

---

### UC-8: 스팟 목록 보기

**목적**: 사용자가 스팟을 목록 형태로 확인한다

**사전 조건**: UC-6 완료

**흐름**:
1. 사용자가 "스팟 목록" 탭을 선택한다
2. 스팟이 거리순으로 정렬되어 표시된다
3. 각 스팟에 다음 정보가 표시된다:
   - 매장 이름
   - 보상 금액
   - 거리
   - 스탬프 진행률 (예: 3/10)
   - 상태 (클레임 가능 / 쿨다운 중 / 소진)
4. 스팟을 탭하면 지도에서 해당 위치로 이동한다

---

### UC-9: 첫 방문 클레임

**목적**: 사용자가 스팟을 처음 방문하여 TON을 받는다

**사전 조건**: UC-7에서 스팟을 확인함

**흐름**:
1. 사용자가 스팟 위치로 이동한다
2. 스팟 50m 이내에 도달한다
3. 스팟을 선택하고 "클레임" 버튼을 누른다
4. 시스템이 검증한다:
   - 위치: 50m 이내인가?
   - 시간: 활성 시간대인가?
   - 속도: 비정상 이동이 아닌가?
5. 검증 통과 → 스마트 컨트랙트에서 클레임 실행
6. 결과 표시:
   - "0.1 TON 획득!"
   - "스탬프 1/10"
7. 잔액이 갱신된다

**예외**:
- 50m 밖 → "너무 멀어요 (XXm). 스팟에 더 가까이 가주세요"
- 활성 시간 아님 → "활성 시간이 아닙니다 (09:00~22:00)"
- 비정상 속도 → "비정상적 이동이 감지되었습니다"
- TON 소진 → "이 스팟의 TON이 소진되었습니다"

---

### UC-10: 재방문 클레임

**목적**: 사용자가 같은 스팟을 다시 방문하여 TON을 받는다

**사전 조건**: UC-9로 해당 스팟을 이전에 클레임한 적 있음

**흐름**:
1. 사용자가 이전에 방문한 스팟 위치로 다시 이동한다
2. 스팟 50m 이내에 도달한다
3. 스팟 정보에 스탬프 현황이 표시된다 (예: 3/10)
4. "클레임" 버튼을 누른다
5. 시스템이 쿨다운을 확인한다:
   - 쿨다운 경과 → 클레임 진행
   - 쿨다운 미경과 → 남은 시간 표시
6. 검증 통과 → 클레임 실행
7. 결과 표시:
   - "0.1 TON 획득!"
   - "스탬프 4/10"

**예외**:
- 쿨다운 미경과 → "다음 클레임까지 XX시간 XX분 남았습니다"

---

### UC-11: 스탬프 달성 보너스

**목적**: 사용자가 스탬프 목표를 달성하여 보너스를 받는다

**사전 조건**: UC-10으로 스탬프를 누적해옴

**흐름**:
1. 사용자가 스팟에서 클레임한다 (스탬프 9/10 상태)
2. 스탬프가 10/10이 된다 (목표 달성)
3. 시스템이 1회 보상 + 스탬프 보너스를 함께 지급한다
4. 결과 표시:
   - "0.1 TON + 보너스 2 TON 획득!"
   - "스탬프 달성! 총 2.1 TON 획득!"
   - "스탬프가 리셋되었습니다 (0/10)"
5. 스탬프가 0으로 리셋되어 다시 처음부터 시작

---

### UC-12: 클레임 히스토리 확인

**목적**: 사용자가 자신의 클레임 내역을 확인한다

**사전 조건**: UC-9 이상 완료 (클레임 내역 있음)

**흐름**:
1. 사용자가 히스토리를 조회한다
2. 클레임 내역이 최신순으로 표시된다:
   - 매장 이름
   - 받은 TON (보너스 포함 여부)
   - 클레임 시각
3. 총 획득 TON이 상단에 표시된다

---

### UC-13: 잔액 확인

**목적**: 사용자가 현재 보유한 TON 잔액을 확인한다

**사전 조건**: UC-6 완료

**흐름**:
1. 화면 상단에 현재 잔액이 항상 표시된다
2. 잔액을 탭하면 상세 정보가 표시된다:
   - 현재 잔액
   - 오늘 획득한 TON
   - 총 획득한 TON

---

## 유즈케이스 관계도

```
[점주]
  ├── UC-1: 지갑 연결
  ├── UC-2: TON 충전
  ├── UC-3: 스팟 생성 ──── (UC-2 필요)
  ├── UC-4: 스팟 재예치 ── (UC-3 필요)
  └── UC-5: 방문 현황 확인 (UC-3 필요)

[사용자]
  ├── UC-6: 지갑 연결
  ├── UC-7: 주변 스팟 탐색 ── (UC-6 필요)
  ├── UC-8: 스팟 목록 보기 ── (UC-6 필요)
  ├── UC-9: 첫 방문 클레임 ── (UC-7 필요)
  ├── UC-10: 재방문 클레임 ── (UC-9 필요)
  ├── UC-11: 스탬프 보너스 ── (UC-10 반복)
  ├── UC-12: 클레임 히스토리 (UC-6 필요)
  └── UC-13: 잔액 확인 ───── (UC-6 필요)
```

---

## 핵심 플로우 요약

### 점주의 핵심 플로우
```
지갑 연결 → TON 충전 → 스팟 생성 → 방문 현황 확인 → (소진 시) 재예치
```

### 사용자의 핵심 플로우
```
지갑 연결 → 주변 스팟 탐색 → 매장 방문 → 클레임 → 스탬프 누적 → 보너스 획득
```

## API 매핑

| 유즈케이스 | API 엔드포인트 | 컨트랙트 함수 |
|-----------|---------------|--------------|
| UC-2: TON 충전 | POST /api/faucet | deposit() |
| UC-3: 스팟 생성 | POST /api/spots | createSpot() |
| UC-4: 스팟 재예치 | POST /api/spots/:id/redeposit | redeposit() |
| UC-7: 스팟 탐색 | GET /api/spots | getAllSpots() |
| UC-9~11: 클레임 | POST /api/claim/request | claim() |
| UC-12: 히스토리 | GET /api/claim/history | getClaimHistory() |
| UC-13: 잔액 확인 | GET /api/faucet/balance | getBalance() |
| 스탬프 현황 | GET /api/stamps/:spotId | getStampInfo() |
